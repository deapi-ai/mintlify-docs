In addition to the HTTP API, deAPI exposes an **MCP (Model Context Protocol) server**. This allows AI assistants, IDE extensions, and MCP-aware tools to call deAPI capabilities as structured tools instead of manually constructing HTTP requests.

---

### What is MCP?

The **Model Context Protocol (MCP)** is an open standard that enables AI models and agents to interact with external tools and services in a structured way. Instead of crafting raw HTTP requests, your AI assistant discovers available tools and calls them using a standardized protocol.

With deAPI's MCP server, Claude, ChatGPT, Cursor, and other MCP-compatible clients can:

- Generate images, videos, and audio directly within conversations
- Transcribe YouTube / X / Twitch / Kick / TikTok videos or audio files
- Remove image backgrounds and upscale images and videos
- Check pricing before running expensive operations
- Access all deAPI capabilities through natural language

New tools and capabilities will be added as the MCP server evolves. Follow our [Discord](https://discord.com/invite/UFfK5YRBsr) for updates and to share feature requests.

The full source code for the MCP server is available on GitHub: [github.com/deapi-ai/mcp-server-deapi](https://github.com/deapi-ai/mcp-server-deapi)

### Server Details

| Property                | Value                                                        |
| ----------------------- | ------------------------------------------------------------ |
| **MCP Server URL**      | `https://mcp.deapi.ai/mcp`                                   |
| **Transport**           | Streamable HTTP (there is no SSE endpoint)                   |
| **API key header**      | `Authorization: Bearer <key>` or `X-API-Key: <key>`          |
| **OAuth Client ID**     | `deapi-mcp`                                                  |
| **OAuth Client Secret** | Your deAPI API key                                           |
| **Setup page**          | [mcp.deapi.ai](https://mcp.deapi.ai/): copy-ready setup for each client |

Create an API key at [app.deapi.ai/settings/api-keys](https://app.deapi.ai/settings/api-keys). Jobs run on your deAPI balance, so treat the key like a password.

### Authentication

Every request carries your deAPI API key, in one of two ways:

- **In a header** (Claude Code, Cursor, VS Code, Codex, Gemini CLI and most other clients): `Authorization: Bearer <key>`, or `X-API-Key: <key>` for a client that only lets you name one header. When both are sent, `Authorization` is used.
- **Through OAuth with the deAPI sign-in window** (claude.ai, Claude Desktop, ChatGPT, and any client that registers itself): add the server URL and connect. A deAPI sign-in window opens, shows which application is asking and where the access goes, and asks for your API key. The server supports dynamic client registration and client ID metadata documents, with the Authorization Code flow and PKCE (S256).
- **Through OAuth with the pre-registered client** (for clients where you enter OAuth credentials yourself): Client ID `deapi-mcp`, Client Secret = your API key. No sign-in window is shown.

The key is checked with deAPI when the client connects. A key deAPI does not accept is refused with `401` right away (or `invalid_client` during OAuth sign-in), so an authentication error from your client means the key needs fixing. Never put the key in the URL: the server only reads it from the headers above.

### Working with Results

Generation tools wait for the job to finish and return its outcome in one call:

```json
{
  "success": true,
  "result": null,
  "result_url": "https://results.deapi.ai/21661623/4d04b54c-….txt?X-Amz-…",
  "job_id": "a8d972db-252a-4204-be62-26f248247177",
  "metadata": { "elapsed_time": 8.39, "attempts": 5 },
  "price": { "amount": 0.0052474, "is_estimated": false }
}
```

- **`result_url`** points to the output file. Images, video and audio always come back this way.
- **`result`** carries text inline (transcripts, OCR, embeddings) when `return_result_in_response` is `true`. With `WhisperLargeV3Ct2`, `result` is a JSON string with `text`, `language` and, when timestamps are requested, `segments`.
- **`price.amount`** is what the job cost.

**Long transcripts.** Some MCP clients cap how much of a tool result they pass to the model and drop the rest. For long videos, call the transcription tool with `return_result_in_response: false`: the transcript stays out of the tool result and the tool returns `result_url`, a signed link to the full transcript file. This helps only if the client passes the link to the model: Parallel's Task API, for example, replaces `result_url` with `[redacted]`, so the agent never receives the transcript. With such clients, keep `return_result_in_response: true` and accept that only the part that fits in the client's limit gets through (25,000 characters on Parallel).

**Pricing a URL transcription.** `video_url_transcription_price` accepts either `video_url` or `duration_seconds`, not both. With a URL, the price is read from the source itself. TikTok links can't be quoted by URL — pass `duration_seconds` together with `platform: "tiktok"`. The platform changes the price, so set `platform` whenever you quote by duration.

**Webhooks.** All 18 generation tools accept `webhook_url` and an optional `webhook_secret`, and pass them to the API. deAPI then calls your endpoint when the job finishes, so your own systems are notified as well. The tool still waits and returns the result in the conversation. See [Webhooks](/execution-modes-and-integrations/webhooks) for the payload and signature.

### How to Connect

#### Claude (claude.ai and Claude Desktop)

claude.ai and the Claude Desktop app share the same connector settings. To use deAPI MCP tools in Claude conversations:

**Step 1.** Create an API key at [app.deapi.ai/settings/api-keys](https://app.deapi.ai/settings/api-keys)

**Step 2.** Add the connector:

- Open **Customize** → **Connectors** and choose **Add custom connector**
- Name it `deAPI` and enter the server URL `https://mcp.deapi.ai/mcp`

**Step 3.** Click **Add**, then **Connect**. A deAPI sign-in window opens: paste your API key and choose **Allow access**. Claude then lists the deAPI tools.

<Note>
  To skip the sign-in window, open **Advanced settings** before adding the connector, choose **Use your own OAuth client**, and enter Client ID `deapi-mcp` with your API key as Client Secret. Where your plan offers **Request headers** for custom connectors, you can also choose no sign-in and add the header `Authorization: Bearer <your key>`. On Team and Enterprise plans, an owner adds connectors under Organization settings.
</Note>

**Step 4.** Start using deAPI MCP by asking Claude to generate images, transcribe videos, or use any other capability. Make sure to mention "deAPI MCP" in your prompt so Claude knows to use the MCP tools.

**Example prompts:**

- _"Using deAPI MCP, generate an image of a futuristic city at sunset"_
- _"With deAPI MCP, transcribe this YouTube video: [URL]"_
- _"With deAPI MCP, transcribe this Twitch video: [URL]"_
- _"With deAPI MCP, transcribe this TikTok with WhisperLargeV3Ct2: [URL]"_
- _"Check my deAPI MCP balance"_
- _"Using deAPI MCP, create a video of waves crashing on a beach"_

#### Cursor IDE

To integrate deAPI MCP into Cursor for AI-assisted development:

<Tip>
  **Quick setup:** Press `Cmd+Shift+P` (macOS) or `Ctrl+Shift+P` (Windows/Linux), type **"MCP Settings"** and press Enter — this opens the MCP configuration file directly.
</Tip>

**Step 1.** Create an API key at [app.deapi.ai/settings/api-keys](https://app.deapi.ai/settings/api-keys)

**Step 2.** Open Cursor Settings:

- Press `Cmd/Ctrl + Shift + P`
- Search for **"Cursor Settings"** or navigate to **Settings** → **Cursor Settings**

**Step 3.** Add MCP Configuration:

- Find the **MCP** or **Model Context Protocol** section
- Add a custom MCP server configuration
- Paste the following JSON into `~/.cursor/mcp.json` (or `.cursor/mcp.json` in a project). It reads the key from the `DEAPI_API_KEY` environment variable, so the key stays out of the file:

```json
{
  "mcpServers": {
    "deapi": {
      "url": "https://mcp.deapi.ai/mcp",
      "headers": {
        "Authorization": "Bearer ${env:DEAPI_API_KEY}"
      }
    }
  }
}
```

If you prefer Cursor's OAuth sign-in, use the pre-registered client instead:

```json
{
  "mcpServers": {
    "deapi": {
      "url": "https://mcp.deapi.ai/mcp",
      "auth": {
        "CLIENT_ID": "deapi-mcp",
        "CLIENT_SECRET": "${env:DEAPI_API_KEY}"
      }
    }
  }
}
```

**Step 4.** Restart Cursor to apply the configuration.

**Step 5.** Invoke deAPI MCP in chat by using phrases like:

- _"Using deAPI MCP, generate an image of…"_
- _"With deAPI MCP, transcribe this audio…"_
- _"Via deAPI MCP, check my balance"_

<Tip>
  Cursor recognizes deAPI MCP tools when you mention keywords like "using deAPI MCP", "with deAPI MCP", or "via MCP" in your prompts.
</Tip>

#### Claude Code

To use deAPI MCP in Claude Code, open a terminal in your project directory and run:

```bash
export DEAPI_API_KEY="YOUR_API_KEY"
claude mcp add deapi -s user -t http https://mcp.deapi.ai/mcp --header "Authorization: Bearer $DEAPI_API_KEY"
```

Replace `YOUR_API_KEY` with your actual deAPI key. The server will be available in all your Claude Code sessions.

To share the server with a project, add it to `.mcp.json` instead; Claude Code expands `${DEAPI_API_KEY}` from the environment:

```json
{
  "mcpServers": {
    "deapi": {
      "type": "http",
      "url": "https://mcp.deapi.ai/mcp",
      "headers": { "Authorization": "Bearer ${DEAPI_API_KEY}" }
    }
  }
}
```

### Self-Hosting

You can run the MCP server on your own infrastructure. The full source code is available at [github.com/deapi-ai/mcp-server-deapi](https://github.com/deapi-ai/mcp-server-deapi) under the MIT license.

#### Prerequisites

- Python 3.11 or higher
- `uv`, `pip`, or `conda` for package management
- A deAPI API key from [app.deapi.ai/settings/api-keys](https://app.deapi.ai/settings/api-keys)

#### Quick Start

```bash
git clone https://github.com/deapi-ai/mcp-server-deapi.git
cd mcp-server-deapi

# Install dependencies (uv recommended)
uv pip install -e .

# Start the server on your machine only
MCP_HOST=127.0.0.1 python -m deapi_mcp.server_remote
```

The server will start on `http://localhost:8000`. For external access, set a fixed key for signing OAuth tokens first; the server refuses to start beyond localhost without one:

```bash
export DEAPI_JWT_SECRET_KEY=$(python -c "import secrets; print(secrets.token_urlsafe(32))")
MCP_HOST=0.0.0.0 MCP_PORT=8000 python -m deapi_mcp.server_remote
```

#### Docker Deployment

```bash
# Build and run
docker build -t mcp-server-deapi .
docker run -d -p 8000:8000 -e DEAPI_JWT_SECRET_KEY="$DEAPI_JWT_SECRET_KEY" --name mcp-server-deapi mcp-server-deapi

# Or with Docker Compose
docker-compose up -d
```

#### Cloud Deployment Options

The server can be deployed to any platform that supports Python or Docker containers: Railway, Fly.io, Heroku, DigitalOcean App Platform, AWS ECS, GCP Cloud Run, and others. Detailed deployment instructions are available in [DEPLOYMENT.md](https://github.com/deapi-ai/mcp-server-deapi/blob/main/DEPLOYMENT.md) in the repository.

#### Connecting a Self-Hosted Server

Point your MCP client to your server URL instead of the default `https://mcp.deapi.ai/mcp`:

```json
{
  "mcpServers": {
    "deapi": {
      "url": "http://your-server-ip:8000/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}
```

### Architecture

#### Smart Adaptive Polling

For async jobs, the server automatically polls for results with optimized intervals based on job type:

| Job Type | Initial Delay | Max Delay | Timeout |
| -------- | ------------- | --------- | ------- |
| Audio    | 1s            | 5s        | 5 min   |
| Image    | 2s            | 8s        | 5 min   |
| Video    | 5s            | 30s       | 15 min  |

Polling uses exponential backoff (1.5× multiplier by default), so jobs receive fast initial checks while heavier workloads avoid unnecessary load.

#### Token Security

The MCP server does **not** store your API token. Authentication works at the connection level:

- **Remote hosted server**: OAuth 2.0 Authorization Code with PKCE (pre-registered client `deapi-mcp`), or your API key in the `Authorization: Bearer` or `X-API-Key` header
- **Key check**: the key is checked with deAPI when a client connects, and a key deAPI refuses gets `401` immediately
- **Self-hosted server**: the key is forwarded per request to the deAPI API
- Keys are never persisted or logged, and never read from the URL; tools do **not** accept `deapi_api_token` as a parameter

### When to Use MCP vs HTTP API

| Use Case                           | Recommended    |
| ---------------------------------- | -------------- |
| AI assistants & chatbots           | **MCP Server** |
| IDE integrations (Cursor, VS Code) | **MCP Server** |
| Terminal AI tools (Claude Code, Codex, Gemini CLI) | **MCP Server** |
| Backend services & workers         | **HTTP API**   |
| Batch processing                   | **HTTP API**   |
| Direct programmatic control        | **HTTP API**   |
| Agent-driven workflows             | **MCP Server** |

Use the **MCP server** when you want an AI agent to decide which tools to call, with which parameters, and in what order. Use the **HTTP API + queue** for typical backend integrations where you directly manage requests and results.

### Troubleshooting

#### Connection Issues

- **Verify your API key** is valid and has sufficient balance
- **Check the server URL** is exactly `https://mcp.deapi.ai/mcp`
- **For Claude and ChatGPT:** If the deAPI sign-in window says the key was not accepted, copy the key again; if you entered OAuth credentials yourself, the Client ID must be `deapi-mcp` and the Secret your API key
- **"Unverified application" in the sign-in window:** the application registered itself and deAPI cannot confirm who runs it. Continue only if you started the connection and recognise the address shown under **Access goes to**
- **For header-based clients:** The header should be `Authorization: Bearer YOUR_API_KEY` (with the `Bearer ` prefix) or `X-API-Key: YOUR_API_KEY`
- **`401` or `invalid_client` when connecting:** deAPI did not accept the key. Copy it again from [app.deapi.ai/settings/api-keys](https://app.deapi.ai/settings/api-keys), or create a new one

#### Tools Not Appearing

- Restart your MCP client (Claude, ChatGPT, Cursor) after configuration changes
- **In Claude:** Make sure you clicked **Allow** when prompted to grant permissions
- **In ChatGPT:** Ensure Developer mode is enabled in Advanced settings
- Verify JSON syntax in configuration files (Cursor, VS Code, Claude Code)
- Check that your API key has the necessary permissions

#### Jobs Stuck in Processing

- Use `check_job_status` tool with the job ID to monitor progress
- Large video generation or transcription jobs may take several minutes
- Check [status.deapi.ai](https://status.deapi.ai/) for system status

#### Remote Connection Issues (Self-Hosted)

- Test the server: `curl http://your-server:8000/health` should return `{"status": "healthy", ...}`, and `POST /mcp` without a key should return `401`
- Check server logs: `docker logs mcp-server-deapi` or `journalctl -u mcp-server-deapi`
- Verify firewall rules allow the configured port
- For SSL issues, confirm certificates are valid and paths are correct in your proxy config
