Unified transcription endpoint that replaces the five v1 endpoints (`vid2txt`, `aud2txt`, `videofile2txt`, `audiofile2txt`, `transcribe`). Accepts URLs or multipart file uploads. Returns a `request_id` for status polling.

<Info>
  Source detection is automatic: pass a public URL in `source_url` (audio and video both use this one field), or upload a file via multipart `source_file`. There are no `video_url` / `audio_url` fields.
</Info>

<Note>
  **Prerequisite:** Consult the [Model Selection](/api/v2/utilities/models) endpoint to identify a valid model `slug` and check supported languages.
</Note>

<Tip>
  **OpenAI SDK users:** This endpoint is also available via the OpenAI-compatible surface as `POST /v1/audio/transcriptions` at `https://oai.deapi.ai/v1`. Maximum file size per upload is **20 MB for audio** and **50 MB for video**, subject to a global **75 MB** request body cap. See [OpenAI Compatibility](/openai-compatibility) and [Limits & Quotas](/limits-and-quotas#file-uploads).
</Tip>

`WhisperLargeV3` supports `segment` timestamps only and does not support diarization. `WhisperLargeV3Ct2` adds `word`-level timestamps, per-segment confidence scores and speaker labels.

**Segment timestamps are free.** `include_ts: true` with the default `ts_level: "segment"` costs exactly the same as a plain transcription — on every model, `WhisperLargeV3Ct2` included. Only finer granularity is billed: on `WhisperLargeV3Ct2`, `ts_level: "word"` or `"char"` — and `diarize`, which carries the surcharge at *any* granularity, `segment` included — multiplies the duration-based price by 1.5. See [Pricing](/pricing).

<Warning>
  **Granularity is validated against the model.** The levels a model accepts are published as `info.limits.timestamp_levels` by [GET /api/v2/models](/api/v2/utilities/models). `WhisperLargeV3` publishes `["segment"]` and `supports_diarization: false`, so `ts_level: "word"` or `"char"` is rejected with `422` and an `errors.ts_level` entry, and `diarize: true` is rejected with `422` and an `errors.diarize` entry. Read the model's advertised levels before sending anything other than `segment`. See [Errors](/api/v2/errors).
</Warning>

**A source with no speech returns an empty result, not an error.** If the video or audio carries no recognisable words — silence, music only, ambient noise — the job still completes with `status: "done"` and the transcript comes back empty: no segments, no words, no speakers. Treat an empty transcript as a valid outcome and branch on it explicitly, rather than assuming the job failed. A job that genuinely failed reports `status: "error"` with an `error_reason` instead.

## Source metadata

Set `include_metadata: true` to have the job-status response carry a `metadata` object describing the source — title, channel, uploader, upload date and engagement counts.

<Warning>
  Metadata is a **paid add-on: 0.005 USD per request**. It is charged only on sources that can actually return it, so an uploaded file — which has no source to describe — returns `null` and is never charged. See [Pricing](/pricing).
</Warning>

Only URL sources have metadata, and how much you get depends on the platform. The field names are the same either way, and anything a platform does not expose comes back as `null` rather than being omitted.

| Metadata | TikTok | YouTube |
| --- | :-: | :-: |
| `id`, `title`, `description`, `channel` | ✅ | ✅ |
| `duration_seconds`, `extractor` | ✅ | ✅ |
| `view_count`, `like_count` | ✅ | ✅ |
| `comment_count` | ✅ | ❌ |
| `repost_count`, `save_count` | ✅ | ❌ |
| `uploader`, `uploader_url` | ✅ | ❌ |
| `channel_id`, `channel_url` | ✅ | ❌ |
| `webpage_url` | ✅ | ❌ |
| `timestamp`, `upload_date` | ✅ | ❌ |
| `thumbnails[]` | ✅ | ❌ |
| `fulltitle`, `has_audio`, `is_live` | ✅ | ❌ |
| `tags`, `categories`, `chapters`, `heatmap`, `availability`, `channel_follower_count` | ✅\* | ❌ |

\* Present in the response schema, but may come back `null` depending on the individual TikTok video.
